# Sniffer

Мобильное приложение для оповещения об опасных ситуациях в квартирах, оснащённых газовым оборудованием.

## О проекте

Обычные газовые сигнализации подают только локальный звуковой сигнал, который бесполезен, если дома никого нет. Sniffer — это умная система для жилых помещений: датчик следит за состоянием воздуха, данные в реальном времени попадают в облако, а Android-приложение показывает их пользователю и отправляет уведомление на телефон при опасности.

## Возможности

- **Сенсорные данные** — температура, влажность, давление и IAQ в реальном времени.
- **Live-график** — до 20 последних точек, переключение между показателями нажатием на карточку.
- **Сценарии состояния воздуха** — по одной alert-карточке на каждый сценарий:

  | Сценарий | Порог |
  |---|---|
  | Сухой воздух | влажность < 30% |
  | Плесень | влажность > 65% |
  | Застой воздуха | IAQ > 100 |
  | Дым | IAQ > 180 + скачок температуры |

  Набор сценариев можно расширять.
- **Уведомления** — foreground-сервис следит за воздухом, даже когда приложение закрыто, и отправляет push при опасном сценарии.
- **Авторизация** — вход и регистрация через Firebase Auth, сохранение сессии, выход из аккаунта.

## Аппаратная часть

| Компонент | Описание |
|---|---|
| Микроконтроллер | ESP-WROOM-32 |
| Сенсор | Bosch BME680 (температура, влажность, давление, IAQ) |
| Протокол | I2C |
| Питание | 5 V |
| Связь | Wi-Fi → Firebase |

## Как это работает

```
ESP-WROOM-32 + BME680  ──►  Firebase Realtime Database  ──►  Android-приложение
  опрос каждые 5 сек         узел /bme680 обновляется         ValueEventListener → StateFlow → Jetpack Compose
```

1. ESP снимает данные с BME680 каждые 5 секунд и записывает их в узел `/bme680`.
2. Приложение подписывается на узел через Firebase SDK (`ValueEventListener`).
3. UI реагирует на изменения через `StateFlow`.

### Экраны

- **LoginScreen** — единый экран входа и регистрации: валидация email и пароля, переведённые сообщения об ошибках Firebase, индикатор загрузки, автоматическое сохранение сессии.
- **MainScreen** — четыре сенсорные карточки с последними показаниями, график выбранного показателя (история до 20 точек хранится в репозитории), прокручиваемый список карточек состояния среды, кнопка выхода.

### Фоновый мониторинг

```
Firebase RTDB ─► SensorMonitorService ─► AirQualityAdvisor ─► Уведомление
 ValueEventListener   ForegroundService      isSmokeAlert()     IMPORTANCE_HIGH
```

- `START_STICKY` — сервис перезапускается, если его завершила ОС; при перезапуске проверяет `currentUser` и останавливается, если пользователь не авторизован.
- Два канала уведомлений: `sniffer_monitor` (LOW) — тихое постоянное уведомление, `sniffer_smoke_alert` (HIGH) — звук и вибрация при опасности.
- Флаг `smokeAlertActive` защищает от спама: уведомление отправляется один раз за событие и сбрасывается после нормализации показателей.

## Архитектура

Clean Architecture + MVVM.

| Слой | Состав |
|---|---|
| **Presentation** | Screens, ViewModels, Navigation, ForegroundService |
| **Data** | `FirebaseSensorRepositoryImpl`, `FirebaseUserRepositoryImpl`, `AndroidNotificationService` |
| **Domain** | `SensorData`, `SensorRepository`, `UserRepository`, `NotificationService`, `AirQualityAdvisor` |

В слое Presentation используется MVVM: `StateFlow` / `mutableStateOf` → рекомпозиция Compose.

## Технологии

**Аппаратная часть**
- ESP-WROOM-32 — Wi-Fi, готовые библиотеки для Firebase SDK и BME680
- BME680 — четыре параметра в одном сенсоре
- Firebase Realtime Database — push-модель: приложение слушает изменения узла и реагирует на них

**Android**
- Kotlin — null-safety, корутины
- Jetpack Compose — декларативный UI
- ForegroundService — мониторинг при закрытом приложении
- Firebase Auth — готовая авторизация и кэш сессии
